# План портфолио

## Цель

Создать структурированное портфолио системного аналитика для поиска работы в России.

Портфолио должно демонстрировать практические навыки анализа и проектирования систем на примере связанных проектных артефактов.

---

## Основной проект

### Smart Home Management Platform

Система управления умным домом используется как основной сквозной кейс.

Проект должен показывать работу системного аналитика на разных уровнях:

- требования;
- процессы;
- данные;
- API;
- системные взаимодействия;
- архитектура.

---

## Структура основного проекта

```text
smart-home/
├── requirements/
├── bpmn/
├── erd/
├── sql/
├── api/
├── uml/
├── architecture/
├── wireframes/
└── README.md
```

---

## Требования

Портфолио должно содержать:

- Vision;
- Stakeholders;
- Business Goals;
- Scope;
- Functional Requirements;
- Non-functional Requirements;
- User Stories;
- Use Cases;
- Business Rules;
- Glossary.

---

## Моделирование процессов

Необходимо показать несколько ключевых процессов системы.

Основные сценарии:

- регистрация пользователя;
- подключение устройства;
- управление устройством.

Для процессов используются BPMN-диаграммы.

---

## Модель данных

Проект должен содержать:

- ERD;
- описание сущностей;
- PK/FK;
- связи между сущностями;
- ограничения целостности.

---

## SQL

Необходимо показать:

- создание таблиц;
- внешние ключи;
- ограничения;
- индексы;
- запросы с `JOIN`;
- агрегирование данных;
- выборки по основным бизнес-сценариям.

---

## API

REST API документируется с использованием OpenAPI.

Необходимо показать:

- endpoints;
- HTTP methods;
- request body;
- response body;
- HTTP status codes;
- authentication;
- основные схемы данных.

---

## UML

Sequence Diagrams используются для демонстрации взаимодействия компонентов.

Основные сценарии:

- User Registration;
- Add Device;
- Device Control.

---

## Архитектура

Архитектурная документация должна показывать:

- клиентское приложение;
- Backend;
- базу данных;
- компонент взаимодействия с IoT;
- устройства;
- основные протоколы обмена.

---

## Wireframes

Wireframes являются дополнительным этапом развития проекта.

Их отсутствие не блокирует использование портфолио для откликов.

---

## Критерии качества

Перед публикацией необходимо проверить:

- отсутствие дубликатов;
- отсутствие временных файлов;
- работающие ссылки;
- единый язык документации;
- актуальные статусы;
- соответствие API модели данных;
- читаемость диаграмм;
- понятную навигацию из главного README.

---

## Целевая версия

Первая публичная версия портфолио предназначена для откликов на вакансии:

- стажёр системного аналитика;
- Junior System Analyst;
- Junior+ System Analyst;
- системный аналитик на позиции с требованиями 1–3 года, если стек и задачи вакансии соответствуют фактическим навыкам кандидата.
