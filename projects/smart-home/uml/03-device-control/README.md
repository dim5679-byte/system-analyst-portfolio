# Device Control — Sequence Diagram

## Назначение

Диаграмма последовательности описывает взаимодействие компонентов Smart Home Management Platform при отправке команды IoT-устройству и получении результата её выполнения.

---

## Участники

- `User` — пользователь системы;
- `Mobile App` — клиентское приложение;
- `Smart Home Backend` — серверная часть системы;
- `Database` — база данных PostgreSQL;
- `IoT Device` — подключенное умное устройство.

---

## Основной сценарий

1. Пользователь выбирает действие для устройства.
2. Mobile App отправляет `POST /devices/{deviceId}/commands`.
3. Backend проверяет права пользователя и доступность устройства.
4. Backend создаёт команду со статусом `pending`.
5. Backend возвращает `202 Accepted`.
6. Команда отправляется IoT-устройству.
7. IoT-устройство выполняет команду и возвращает результат.
8. При успешном выполнении статус команды изменяется на `completed`, а состояние устройства обновляется.
9. При ошибке выполнения статус команды изменяется на `failed`.
10. Mobile App запрашивает итоговый статус через `GET /commands/{commandId}`.
11. Backend возвращает текущий статус команды.
12. Mobile App отображает пользователю результат выполнения.

---

## Альтернативные сценарии

### Нет доступа к устройству

Если пользователь не имеет доступа к устройству, Backend возвращает:

`403 Forbidden`

Mobile App отображает сообщение об ошибке доступа.

### Устройство недоступно

Если устройство недоступно для выполнения команды, Backend возвращает:

`409 Conflict`

Mobile App сообщает пользователю, что устройство недоступно.

### Ошибка выполнения команды

Если IoT-устройство не смогло выполнить команду, статус команды изменяется на:

`failed`

Итоговый статус возвращается клиентскому приложению при запросе состояния команды.

---

## Статусы команды

В сценарии используются следующие статусы:

- `pending` — команда создана и ожидает выполнения;
- `completed` — команда успешно выполнена;
- `failed` — команда завершилась с ошибкой.
